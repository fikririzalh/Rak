Data Mining · Klasifikasi Berbasis Aturan

Rule-Based Classifier

Tujuan Pembelajaran

  • Menjelaskan bentuk aturan (Condition) → y beserta istilah LHS/RHS dan konsep covers.
  • Menghitung coverage dan accuracy sebuah aturan dari tabel data.
  • Membedakan aturan mutually exclusive dan exhaustive, serta menyelesaikan masalah akibat penyederhanaan aturan (ordered rule set dan default class).
  • Menguraikan metode direct (sequential covering, RIPPER) dan indirect (C4.5rules).
  • Menggunakan metrik evaluasi aturan (Accuracy, Laplace, M-estimate, FOIL's gain) untuk memilih conjunct.

Konsep Inti

Rule-based classifier mengklasifikasikan record memakai kumpulan aturan "if…then…". Setiap aturan berbentuk (Condition) → y: Condition adalah konjungsi (AND) dari kondisi atribut, dan y adalah label kelas.

Keunggulan utamanya adalah interpretabilitas: aturan dapat dibaca manusia, sementara daya ekspresinya setara decision tree. Inti pembelajarannya: bagaimana aturan dipakai (mengklasifikasi) dan bagaimana aturan dibangun dari data.

Pembahasan Utama

1. Anatomi aturan dan konsep "covers"

  • LHS (antecedent/kondisi) berada di kiri panah; RHS (consequent) berupa label kelas.
  • Contoh pada slide: (Blood Type=Warm) ∧ (Lay Eggs=Yes) → Birds, dan (Taxable Income < 50K) ∧ (Refund=Yes) → Evade=No.
  • Aturan r mencakup (covers) instance x jika atribut x memenuhi seluruh kondisi aturan tersebut.
AturanKondisi (LHS)Kelas (RHS)
r1Gives Birth = no ∧ Aerial Creature = yesBirds
r2Gives Birth = no ∧ Aquatic Creature = yesFishes
r3Gives Birth = yes ∧ Body Temperature = warm-bloodedMammals
r4Gives Birth = no ∧ Aerial Creature = noReptiles
r5Aquatic Creature = semiAmphibians

Hawk (Gives Birth=no, Aerial=yes) dicakup r1 → Birds. Grizzly bear (Gives Birth=yes, warm-blooded) dicakup r3 → Mammals.

2. Coverage dan accuracy sebuah aturan

  • Coverage = fraksi record yang memenuhi antecedent = |A| / |D|.
  • Accuracy = fraksi record yang memenuhi antecedent dan consequent, dihitung terhadap record yang tercakup = |A ∩ y| / |A|.

Pada tabel 10 record (Refund, Marital Status, Taxable Income, Class), aturan (Status=Single) → No: record bertatus Single adalah Tid 1, 3, 8, 10 (4 dari 10, kelasnya No, No, Yes, Yes). Maka coverage = 4/10 = 40% dan accuracy = 2/4 = 50%, sesuai slide.

3. Cara kerja dan dua masalah: mutually exclusive & exhaustive

  • Mutually exclusive: aturan saling independen, setiap record dicakup paling banyak satu aturan.
  • Exhaustive: aturan menangani semua kombinasi nilai atribut, setiap record dicakup minimal satu aturan.
RecordAturan yang terpicuHasil
lemur (warm, gives birth)r3Mammals
turtle (cold, no birth, aerial no, aquatic semi)r4 dan r5Konflik: Reptiles vs Amphibians (tidak mutually exclusive)
dogfish shark (cold, gives birth, aquatic yes)tidak adaTidak tercakup (tidak exhaustive)

4. Dari decision tree ke aturan dan penyederhanaannya

Setiap jalur akar-ke-daun pada tree menjadi satu aturan. Dari tree Refund → Marital Status → Taxable Income diperoleh empat aturan: (Refund=Yes) → No; (Refund=No, Status={Single,Divorced}, Income < 80K) → No; (Refund=No, Status={Single,Divorced}, Income > 80K) → Yes; (Refund=No, Status={Married}) → No. Himpunan aturan ini mutually exclusive dan exhaustive serta memuat informasi sebanyak tree.

Aturan dapat disederhanakan: (Refund=No) ∧ (Status=Married) → No menjadi (Status=Married) → No. Pada data, semua record Married (Tid 2, 4, 6, 9) berkelas No, jadi penyederhanaan ini valid. Akibatnya aturan tidak lagi mutually exclusive (satu record bisa memicu banyak aturan; solusi: ordered rule set atau unordered rule set dengan skema voting) dan tidak lagi exhaustive (solusi: default class).

5. Ordered rule set (decision list) dan skema pengurutan

  • Aturan diurutkan menurut prioritas. Record diberi kelas dari aturan berperingkat tertinggi yang terpicu; jika tidak ada yang terpicu, diberi default class.
  • Pada contoh turtle, r4 (lebih atas dari r5) menang sehingga turtle diklasifikasikan Reptiles.
  • Rule-based ordering: tiap aturan diurutkan berdasarkan kualitas/prioritasnya sendiri.
  • Class-based ordering: aturan yang sekelas dikelompokkan berdekatan.

7. Direct method: sequential covering

  1. Mulai dengan E = record latih, A = pasangan atribut-nilai, Yo = kelas terurut {y1, …, yk}, dan daftar aturan R = {}.
  2. Untuk tiap kelas y ∈ Yo − {yk}: selama kriteria berhenti belum terpenuhi, bangun satu aturan dengan Learn-One-Rule(E, A, y).
  3. Hapus record dalam E yang dicakup aturan itu, lalu tambahkan aturan ke bagian bawah daftar R.
  4. Setelah semua kelas selesai, tambahkan default rule {} → yk di bagian bawah.

Ilustrasi slide: data berisi titik + dan −; aturan R1 mencakup gugus + pertama, record tercakup dibuang, lalu R2 dan seterusnya dibangun dari sisa data. Lima aspek yang harus dirancang: rule growing (termasuk rule evaluation), instance elimination, stopping criterion, dan rule pruning.

8. Rule growing dan evaluasi aturan

  • General-to-specific: mulai dari aturan kosong {}, lalu menambah conjunct satu per satu.
  • Specific-to-general: mulai dari aturan sangat spesifik (satu record), lalu menggeneralisasi bersama record lain.

Metrik yang menentukan conjunct mana yang ditambahkan (n = instance tercakup, nc = instance tercakup yang kelasnya sama dengan aturan, k = jumlah kelas, p = probabilitas prior):

  • Accuracy = nc / n
  • Laplace = (nc + 1) / (n + k)
  • M-estimate = (nc + k·p) / (n + k)
  • FOIL's information gain (RIPPER): Gain(R0, R1) = t · [ log(p1/(p1+n1)) − log(p0/(p0+n0)) ], dengan t = positif yang dicakup R0 dan R1, p/n = positif/negatif yang dicakup masing-masing aturan.
  • Entropy (CN2): tambahkan conjunct yang meminimalkan entropi; kelas konsekuen = kelas mayoritas pada record tercakup.

Contoh hitung (dari slide rule growing, target kelas Yes; himpunan awal {} berisi 3 Yes dan 4 No, yaitu record dengan Refund=No). Dengan k = 2 dan log basis 2:

ConjunctYes / NoAccuracyLaplaceFOIL gain
Status = Single2 / 12/3 = 0,6673/5 = 0,6002·[log₂(2/3) − log₂(3/7)] ≈ 1,27
Status = Divorced1 / 01/1 = 1,0002/3 ≈ 0,6671·[log₂(1) − log₂(3/7)] ≈ 1,22
Status = Married0 / 301/5 = 0,200t = 0, tidak relevan
Income > 80K3 / 13/4 = 0,7504/6 ≈ 0,6673·[log₂(3/4) − log₂(3/7)] ≈ 2,42

Pelajaran penting: accuracy murni memilih Divorced (100%) padahal hanya mencakup 1 record; Laplace "menghukum" dukungan data yang kecil sehingga Divorced dan Income>80K seri (≈0,667). FOIL gain memperhitungkan jumlah positif yang tercakup, sehingga Income>80K unggul jelas (≈2,42).

9. Instance elimination, stopping criterion, dan pruning

  • Mengapa instance dibuang? Jika tidak, aturan berikutnya identik dengan aturan sebelumnya.
  • Mengapa positif dibuang? Agar aturan berikutnya berbeda.
  • Mengapa negatif dibuang? Agar akurasi aturan tidak diremehkan; slide membandingkan R2 dan R3 pada diagram.
  • Stopping criterion: berhenti bila penambahan conjunct tidak memperbaiki aturan secara signifikan, atau bila aturan mulai mencakup contoh dari kelas lain.
  • Rule pruning mirip post-pruning decision tree. Contohnya reduced error pruning: hapus satu conjunct, bandingkan error pada validation set sebelum dan sesudah, lalu pangkas jika error membaik.

Ringkasan direct method: mulai dengan rule set kosong, ulangi (bangun satu aturan → hapus instance tercakup → pangkas bila perlu → tambahkan ke rule set).

10. RIPPER

  • Dua kelas: pilih satu kelas sebagai positif, pelajari aturannya, dan jadikan kelas negatif sebagai default.
  • Multi-kelas: urutkan kelas menurut prevalensi naik (fraksi instance per kelas), pelajari kelas terkecil dahulu dengan sisanya sebagai negatif, lalu ulangi untuk kelas terkecil berikutnya.
  • Rule growing: mulai dari {} → +; tambahkan conjunct selama FOIL's gain membaik; berhenti ketika aturan tidak lagi mencakup contoh negatif; langsung pangkas dengan incremental reduced error pruning.
  • Ukuran pruning: v = (p − n) / (p + n), dengan p dan n = contoh positif dan negatif yang dicakup aturan pada validation set. Hapus urutan kondisi akhir yang memaksimalkan v.
  • Membangun rule set: sequential covering dengan membuang contoh positif dan negatif yang tercakup. Setiap aturan baru menghitung ulang description length; berhenti jika description length baru lebih panjang d bit dari yang terkecil yang pernah dicapai.

11. C4.5rules (indirect method)

  1. Ekstrak aturan dari setiap jalur akar-ke-daun pada decision tree.
  2. Untuk tiap aturan r: A → y, buat alternatif r': A' → y dengan membuang satu conjunct dari A.
  3. Bandingkan pessimistic error rate r terhadap semua r'; pangkas bila ada r' yang lebih rendah. Ulangi sampai tidak ada perbaikan.
  4. Gunakan class-based ordering: aturan sekelas dikelompokkan, dihitung total description length per kelas, lalu kelas diurutkan menurut description length naik.

Contoh slide (tree Give Birth? → Live in Water? → Can Fly?) menghasilkan: (Give Birth=No, Can Fly=Yes) → Birds; (Give Birth=No, Live in Water=Yes) → Fishes; (Give Birth=Yes) → Mammals; (Give Birth=No, Can Fly=No, Live in Water=No) → Reptiles; () → Amphibians (aturan default).

12. Karakteristik rule-based classifier

  • Seekspresif decision tree, mudah diinterpretasi dan dibangkitkan.
  • Dapat mengklasifikasi instance baru dengan cepat; kinerjanya sebanding dengan decision tree.

Contoh atau Penerapan

Studi kasus sistem akademik (contoh rancangan, bukan dari slide). Aturan untuk memprediksi mahasiswa berisiko:

  • (IPK < 2,0) ∧ (Kehadiran < 75%) → Berisiko
  • (SKS_Lulus_Rendah = ya) → Berisiko
  • {} → Aman (default rule)

Aturan ini berbentuk decision list: aturan teratas yang terpenuhi menentukan kelas. Di SQL, urutan WHEN pada CASE persis mewakili urutan prioritas.

-- Klasifikasi dengan decision list
SELECT nim,
  CASE
    WHEN ipk < 2.0 AND kehadiran < 75 THEN 'Berisiko'
    WHEN sks_lulus_rendah = 1       THEN 'Berisiko'
    ELSE 'Aman'                      -- default class
  END AS kelas
FROM mahasiswa;

-- Coverage & accuracy aturan (Status=Single) -> No
SELECT COUNT(*) * 1.0 / (SELECT COUNT(*) FROM tabel_penipuan) AS coverage,
       SUM(CASE WHEN class = 'No' THEN 1 ELSE 0 END) * 1.0 / COUNT(*) AS accuracy
FROM tabel_penipuan
WHERE marital_status = 'Single';  -- hasil: 0.4 dan 0.5

Rangkuman

Rule-based classifier memakai aturan if-then yang mudah dibaca untuk mengklasifikasi data. Kualitas aturan diukur lewat coverage dan accuracy. Rule set yang tidak mutually exclusive memerlukan pengurutan (decision list), dan yang tidak exhaustive memerlukan default class.

Aturan dapat dibangun secara langsung (sequential covering seperti RIPPER dan CN2) atau tidak langsung dari model lain (C4.5rules). Proses utamanya: menumbuhkan aturan dengan metrik seperti Laplace atau FOIL's gain, membuang instance tercakup, berhenti pada kriteria tertentu, dan memangkas aturan agar tidak overfit. Hasilnya setara decision tree dalam ekspresivitas dan kinerja, namun lebih mudah diinterpretasi.
